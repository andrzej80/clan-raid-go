# Партиция консьюмера стоит

**Алерты:**
- `ConsumerPartitionStuck` (page): пачка партиции не применяется дольше 2 мин;
- `KafkaPartitionPausedLong` (ticket): чтение партиции на паузе 10 мин.

**Влияние.** Встают рейды, попавшие в эту партицию (ключ — `raid_id`). Остальные партиции экземпляра продолжают работать (этап 11, A1).

## Диагностика

1. Найти ошибку и её класс в логе повторов:
   ```bash
   docker logs --since 15m hits-consumer 2>&1 | grep -E "handle batch, will retry|isolate|partition (paused|resumed)" | tail -20
   ```
   В записи есть поле `class`:
   - `transient` — сбой зависимости;
   - `permanent` — битые данные;
   - `unknown` — неизвестно, часто ошибка схемы после релиза.
2. Если `transient` и похоже на блокировку, найти, кто держит строку рейда:
   ```bash
   psql_q "SELECT pid, pg_blocking_pids(pid) AS blocked_by, now() - xact_start AS age, left(query, 80) FROM pg_stat_activity WHERE wait_event_type = 'Lock'"
   ```
3. Если `unknown`, сравнить с последним релизом и миграциями: ошибки вида `column ... does not exist` или `relation ... does not exist`.

## Действия

- **Временный сбой** (база недоступна, блокировка). Устранить причину — консьюмер продолжит сам: пачка обрывается по таймауту попытки (30 с) и повторяется.
- **Постоянная ошибка в данных.** Консьюмер сам делит пачку пополам и отправляет виновную запись в DLQ, партиция продолжает работу без вмешательства. Дальше — [dlq.md](dlq.md).
- **Неизвестная ошибка на каждой записи** (сбой не в данных: релиз, миграция). В DLQ ничего не уходит, повторы продолжаются. Откатить релиз ([rollback.md](rollback.md)) или накатить недостающую миграцию ([migrations.md](migrations.md)).
- **Неизвестная ошибка одной записи.** Через `CONSUMER_RETRY_BUDGET` (по умолчанию 10 мин) запись уйдёт в DLQ сама. Можно дождаться или уменьшить бюджет и перезапустить консьюмер.
- **Пауза без ошибок** (`KafkaPartitionPausedLong`). Горутина партиции не успевает: скорее всего, горячий рейд. См. [consumer-lag.md](consumer-lag.md).

## Проверка

`raidboss_kafka_consumer_retrying_seconds` по партиции вернулся к 0, лаг партиции уменьшается, в логе появилось `kafka partition resumed`.

## Эскалация

Если ошибка `unknown` и откат не помог — разработчикам консьюмера.
