# Откат релиза

**Когда:** после раската сработали `AttackErrorBudgetFastBurn`, `ConsumerPartitionStuck` или `ServiceNotReporting`, и по времени они совпадают с релизом.

## Порядок

1. Зафиксировать время раската и алерты, сохранить логи сбойного сервиса.
2. Вернуть код предыдущего релиза и пересобрать только затронутые сервисы:
   ```bash
   git checkout <предыдущий тег или коммит>
   $DC up -d --build --no-deps <сервис>...
   ```
3. Схему не откатывать. Миграции совместимы с предыдущей версией кода по правилу expand/contract (см. [migrations.md](migrations.md)).
4. Если менялось описание топиков (`internal/kafka/topics.go`), сначала посмотреть, что применилось к кластеру: `go run ./cmd/raidctl topics diff`. Партиции и фактор репликации `topics apply` не меняет, их откат — вручную.

## Что безопасно при откате

- Обработка идемпотентна. Пачки, не закоммиченные новой версией, старая применит повторно без дублей (`hit_id`, `UNIQUE` у наград).
- Удары в Kafka не теряются: offset коммитится только после записи в Postgres.

## Проверка

Алерты погасли, `go run ./cmd/raidctl verify` проходит.
