# Ручное завершение рейда

**Когда:** рейд нужно закрыть досрочно (ошибочно созданный рейд, жалоба, тест в продакшене).

## Как правильно: сдвинуть `ends_at`

Рейд нужно закрыть так, как это сделал бы `scheduler`: в одной транзакции со сменой статуса в outbox должно попасть событие истечения, и подписчики `WatchRaid` должны получить финал. Для этого достаточно сдвинуть срок рейда — `scheduler` закроет его на ближайшем проходе (не позже `SCHEDULER_INTERVAL`, 10 с):

```bash
psql_q "UPDATE raids SET ends_at = now() WHERE id = '<uuid>' AND status = 'active'"
```

После этого удары, принятые позже `ends_at`, консьюмер считает опоздавшими.

## Чего не делать

- `UPDATE raids SET status = 'expired'` напрямую: в outbox не попадёт событие истечения, а подписчики `WatchRaid` останутся без финала до переподключения.
- `UPDATE raids SET status = 'defeated'`: не будет события победы, награды не выдадутся, а инварианты `raidctl verify` (победа ⇔ `killer_hit_id`) нарушатся.

Убить босса досрочно с наградами вручную нельзя: победа определяется только добивающим ударом в консьюмере.

## Проверка

```bash
psql_q "SELECT status, finished_at FROM raids WHERE id = '<uuid>'"
go run ./cmd/raidctl verify --raid <uuid>
```
