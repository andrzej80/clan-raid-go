# Сервис не присылает метрики

**Алерт:** `ServiceNotReporting` (page; для `scheduler` — ticket). От сервиса 3 мин нет ни одной метрики.

**Влияние** зависит от сервиса:
- `api` лежит — удары не принимаются;
- `hits-consumer` лежит — растёт лаг, HP не обновляется;
- `outbox-relay` лежит — не выдаются награды;
- `rewards-worker` лежит — награды не начисляются;
- `scheduler` лежит — рейды не истекают.

## Диагностика

1. Если алерт пришёл сразу по всем сервисам, лежит коллектор телеметрии, а не сервисы:
   ```bash
   $DC ps otel-collector victoriametrics
   ```
2. Состояние контейнера и причина остановки:
   ```bash
   $DC ps <сервис>
   docker logs --tail 50 <контейнер>
   ```
   Типичные причины: `fatal` при старте (нет зависимости, неверный конфиг) или OOM (`docker inspect -f '{{.State.OOMKilled}}' <контейнер>`).
3. Если процесс жив, проверить пробы:
   ```bash
   docker exec <контейнер> wget -qO- http://127.0.0.1:8081/livez
   docker exec <контейнер> wget -qO- http://127.0.0.1:8081/readyz
   ```
   `/livez` 503 — главный цикл завис; снять профиль горутин:
   ```bash
   docker exec <контейнер> wget -qO- "http://127.0.0.1:8081/debug/pprof/goroutine?debug=2" > goroutines.txt
   ```

## Действия

- **Коллектор лежит** — `$DC up -d otel-collector`. Сервисы при этом работают, пропадает только телеметрия.
- **Сервис упал при старте** — устранить причину из лога (зависимость, конфиг). Если это свежий релиз — см. [rollback.md](rollback.md).
- **Завис** (`/livez` 503) — сохранить профиль горутин, затем перезапустить: `$DC restart <сервис>`. Обработка идемпотентна: незакоммиченная пачка после перезапуска применится повторно без дублей.

## Проверка

Метрики сервиса снова приходят, `/readyz` отвечает 200.

## Эскалация

Если сервис падает снова после перезапуска — разработчикам вместе с логом и профилем горутин.
